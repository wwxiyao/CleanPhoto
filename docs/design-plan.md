# CleanPhoto 设计与实施步骤

## 文档目的
把产品需求拆解为可执行的开发步骤，作为后续实现的路线图。

## 总体目标
- 通过“滑动手势”完成照片筛选。
- 删除动作延迟到“批次确认页”，并支持撤回。
- 以 10 张为一组，组内按顺序展示，组间随机抽取。

## 功能拆分与里程碑

### M1：项目骨架与权限
- 接入 `Photos` 权限请求与授权状态处理。
- 加载相册资源（仅读取必要字段：id、创建时间、缩略图/全图）。
- 处理无权限/空相册/首次授权的空态页面。

### M2：批次与排序规则
- 定义“批次”数据结构（10 张为一组）。
- 实现批次抽取策略：从未处理照片中随机抽取 10 张。
- 组内排序规则：按时间顺序（待确认升序/降序）。
- 当剩余照片 < 10 张时，允许不足 10 张的最后一组。
- 已处理的照片必须标记并从后续批次排除。

### M3：照片浏览与手势
- 单张大图展示页（支持上一张/下一张状态管理）。
- 手势映射：
  - 向上滑：加入待删除集合。
  - 向左滑：保留并进入下一张。
- 手势触发后的动效与状态提示（轻量动画即可）。

### M4：待删除确认页
- 批次结束后进入确认页。
- 展示待删除集合（列表或网格）。
- 支持撤回误选（从待删除集合移除）。
- 点击“删除”后调用系统删除 API，完成真实删除。

### M5：批次循环与完成态
- 处理“删除/保留”后的状态更新，进入下一批次。
- 全部处理完后展示完成页（提示已清理完成）。

### M6：细节优化与异常处理
- 处理中途退出后恢复状态（可选：本地缓存当前批次与待删除集合）。
- 删除失败、权限变更、相册资源被外部修改的处理策略。

## 模块设计

### 数据层
- `PhotoAsset`：封装 `PHAsset` 关键字段（id、创建时间、缩略图引用等）。
- `Batch`：一组 10 张的集合 + 排序策略。
- `PendingDeleteSet`：待删除集合（仅存 id）。
- `ProcessedSet`：已处理集合（仅存 id），用于排除重复出现。

### 业务层
- `PhotoLibraryService`：授权、加载、删除。
- `BatchManager`：抽取、排序、批次推进。
- `ReviewSession`：记录待删/已保留/已处理状态。

### 视图层
- `SwipeViewerView`：单张浏览 + 手势。
- `BatchReviewView`：确认页 + 撤回。
- `EmptyStateView`：无权限/无照片。

## 页面流程
1. 启动 -> 权限请求 -> 加载照片。
2. 进入批次浏览页（10 张）。
3. 手势筛选结束 -> 确认页。
4. 确认删除 -> 真正删除 -> 下一批。
5. 处理完成 -> 完成页。

## 关键技术点
- 使用 `PHPhotoLibrary` 读取与删除照片。
- 采用异步加载缩略图，避免大图阻塞 UI。
- 删除操作只在确认页触发。
- 批次内顺序与批次抽取需保证可复现（便于用户理解）。

## 待确认项
- 批次内顺序：时间升序 or 降序。
- 确认页 UI 形式：列表/网格 + 信息密度。
- 是否需要“撤回上一步”手势或按钮。
