# 整理流程可靠性优化

2026-10-26，针对项目评审中的前三项问题实施。

后续交互简化：按用户要求移除右滑撤销和撤销按钮，只保留左滑“保留”、上滑“待删除”；误选待删的照片仍可在批次确认页恢复。以下早期提到的浏览页撤销能力已取消。

手势反馈随后改为固定在照片区域中央的半透明遮罩与大字：上滑红色“待删除”、左滑绿色“保留”。移动超过 24 点后逐渐增强，沿用超过 150 点松手才触发的规则，并显示“继续滑动”或“松手”的提示。照片只轻微跟随手指移动，提示不会滑出边界；收回或不足距离松手会取消。小高度照片使用紧凑文字。对应回归测试总计 37 项通过。

照片布局已取消固定卡片宽高、背景、阴影和叠片。竖屏使用全宽照片区域与紧凑标题、操作栏；横屏将操作区移到右侧。照片按原始比例完整显示，在可用宽高内尽量放大，因此不同画幅仍可能自然留白。布局尺寸与手势方向纳入回归测试，总计 22 项测试通过，iOS 构建通过。

## 已实现的行为

1. **整理进度自动保存。** 每次保留、加入待删、撤销、检查页恢复照片和切换批次时，保存资源 ID、批次顺序、操作历史和检查页状态。重新打开应用并加载获准访问的照片后，恢复原来的位置与选择；恢复时剔除已不可访问的资源。当前显示位置由 BatchManager 统一管理，进入相似页再返回也不会从第一张重新开始。全部整理完成后仍保持完成状态，点击“重新整理”才重置进度。
2. **明确保留整批。** 检查页原来的“暂时跳过”改为“保留本批，继续”。进入下一批时清空本批待删选择；这些照片仍记为已整理，不会累计到下一批待删列表。
3. **删除期间锁定操作。** 全局显示删除进度并禁用页面及工具栏；状态层也阻止恢复、跳批、重新整理、切换模式及重复提交。删除集合在提交前固定，删除成功后才清空选择、刷新照片并进入下一批；失败或系统取消后解除锁定，保留检查页和待删选择。

同步将 BatchManager 的变更通知传递给根视图，使逐张恢复、批次推进和恢复位置及时反映到界面。

## 实现位置

- `CleanPhoto/ReviewSessionStore.swift`：版本化的本地进度快照，使用 UserDefaults，仅存资源 ID 和操作状态，不保存照片内容。
- `CleanPhoto/BatchManager.swift`：恢复、保存、当前位置、显式重置与批次边界。
- `CleanPhoto/LibraryViewModel.swift`：状态通知和删除操作保护。
- `CleanPhoto/ContentView.swift`：统一删除遮罩与重新整理入口。
- `CleanPhoto/SwipeContainerView.swift`：从会话读取当前位置。
- `CleanPhoto/BatchReviewView.swift`：明确保留整批的文案。
- `CleanPhoto/PhotoLibraryService.swift`：抽出服务接口，测试使用可控服务替代系统照片库。

## 验证结果

新增独立 Swift Package 测试入口，直接编译应用的状态管理源码，在 Mac 上运行，无第三方依赖。测试只使用虚拟 PHAsset/PHFetchResult 和可控照片服务，不读取或删除真实照片。

先用旧实现复现三项问题：3 项回归测试共报告 7 个断言失败；修复后加入边界覆盖。最终 12 项测试全部通过：加载不清空决策、跨批次不携带待删、删除锁定、重建对象后恢复与撤销、检查页恢复、照片消失后的正确位置、保留整批后的恢复、完成状态和显式重置、损坏快照回退、删除失败保留状态、成功后推进且防止重复提交、根视图刷新通知。

运行：


## 仍需真机验收

- 整理几张后关闭应用并重新打开，核对照片位置、待删选择和撤销；在检查页关闭应用后也应恢复。
- 在检查页选择“保留本批，继续”，核对后续批次不再带上旧选择。
- 删除弹窗出现时取消或确认，核对恢复、跳批、导航和重复提交被阻止；取消后选择仍在，确认后进入下一批。
- 在部分照片授权、iCloud 下载、系统照片应用外部删除等条件下验证。恢复只针对当时获准访问且仍存在的照片；当前会剔除不可访问 ID，扩大授权后这些照片可能需要重新整理。

相似扫描进度、空间统计、图库变化监听和既有并发隔离警告未纳入本次三项优化。
