# 相似照片回归排查

2026-10-26。对照按需改造前的流式扫描代码、改造后的分页代码，以及当前用户反馈。

后续手机日志进一步确认：即使初始状态正确，固定四轮窗口仍会在约 0.3 秒时过早暂停。现已改为耗时和实际特征计算工作量预算，并增加相册浏览模式。当前行为详见 [相似照片：相册浏览与首次查找](similar-album-browsing.md)；下文保留这一轮排查记录。

## 已确认的问题与来源

| 问题 | 原因 | 来源 | 修复 |
| --- | --- | --- | --- |
| 刚进入就显示“本轮未找到” | 初始 isLoading=false、队列为空，与查找结束但无结果共用同一分支 | 按需改造引入 | 区分尚未开始、排队中、查找中、查找结束；首次响应之前显示查找状态 |
| 首组显示变慢 | 原来每处理出一组就 yield；分页后要等一页最多 10 组完成才返回 | 按需改造引入 | 队列为空时只请求 1 组，立刻发布；随后每次最多补 3 组，目标仍为 10 组 |
| 有结果也要等待缓存落盘 | 每页返回之前同步 await 整个视觉特征缓存保存 | 按需改造引入 | 改为空闲 750 毫秒后合并保存，不阻塞页面返回；使用保存代次防止旧保存任务覆盖新状态 |
| 前 240 张没有结果就停止，容易误解成全库没有 | 将扫描窗口上限直接变成用户可见的停止点 | 按需改造的体验缺口 | 单次补充允许最多 4 个窗口，即至多向前检查 960 张；明确提示只检查了部分照片。仍保留资源上限，不恢复无休止全库扫描 |
| 点随机一组会回到刚跳过的组 | swapAt 把旧组留在队列中，下一次又能抽到它 | 旧实现已有，上次未修复 | 改为“下一组”，当前组从本次会话移除；忽略此组仍是持久化忽略，两者区分 |
| 重进页面重复查找、重复读取缓存 | 每次创建新的 SimilarityService，丢失游标和本次队列 | 旧实现已有，按需模式下更加明显 | LibraryViewModel 复用会话，离开时取消扫描，回来继续未完成的位置；照片授权范围改变时重建会话 |
| 删除后其他组跳动、状态不稳定 | 更新队列时给所有组重新生成 UUID | 按需改造引入 | 保留分组 ID；未变化的组直接保留，选中状态保持 |
| 切组后旧点击可能作用到新组 | 通过数组第一个下标绑定选择，而不是按分组 ID 定位 | 旧代码已有隐患 | 网格使用不可变分组快照，选择操作按 groupID 和 assetID 验证；换组时滚回顶部 |
| 补充期间跳过最后一组，新的补充需求被吞掉 | refillTask 尚在运行时直接忽略 requestRefill | 按需改造引入 | 合并记录用户在加载期间发出的新需求，当前任务结束后按需再执行一次，不因空结果自动无限循环 |
| 超长序列的原有细分优化失效 | 新游标提前截成最多 80 张，旧的“大于 80 张”分支永远不可达 | 按需改造引入 | 游标用一个照片的有界前瞻保留长序列标记，让 2.5 秒细分路径重新生效；恰好 80 张不会误判 |
| 图库未加载完就可能创建空扫描器 | 相似入口没有检查是否已取得 PHFetchResult；空源在缓存会话中会一直被复用 | 旧入口缺少防护，复用会话后风险更明显 | 图库加载完成且有访问权限后才允许进入 |
| 主页面删掉的照片可能仍在缓存相似组里 | 会话复用后需要同步其他入口的删除结果 | 会话复用需配套处理的边界 | 普通批次删除、相似组删除都同步移除缓存队列中的对应资源 |

## 保留的行为

待处理组够用时不发起新的扫描；低于补充阈值时才补充。离开页面、应用失活会取消 Photos 图片请求，取消的页回滚游标，已生成的特征可复用。删除仍经过系统确认，删除失败不改变当前选择。忽略组和磁盘特征缓存仍保留。

## 测试缺口与本次补充

前一版测试主要覆盖队列的数量和边界，没有覆盖初始页面状态、用户连续跳组的语义、首组发布时机，以及实际扫描服务是否等待缓存保存。这些缺口导致“数量正确”但使用起来不正确。

本次将实际 SimilarityService 纳入测试构建，使用可控的视觉验证和缓存边界替代真实照片操作，直接验证生产分页循环。新增用例包含初始空态、首组先发布、跳过不循环、稳定 ID、过期选择、会话复用、补充时的新需求、缓存不阻塞首组、簇内溢出结果复用、取消后的游标恢复和局部窗口非全库结束。

最终 62 项测试通过，iOS 未签名构建通过；另覆盖了长序列标记、原有细分路径、图库加载入口与普通批次删除后的缓存一致性。

## 性能与剩余边界

本次没有降低相似度阈值，也没有通过丢掉云端照片来伪造提速。iCloud 下载、首个候选簇的 Vision 分析、首次读取已有的大缓存仍可能耗时；修复首先消除了不必要的整页等待、前台缓存写入和重复扫描。已增加不包含照片内容或资源 ID 的页耗时日志，便于在真实图库进一步核对耗时。

虚拟数据测试证明流程与边界，不代表已测得真实图库的固定提速倍数。新拍照片的实时监听、照片编辑后的特征缓存失效、忽略组恢复入口属于原有产品缺口，本次未声称解决。
