# CleanPhoto 功能盘点与优化建议

评审日期：2026-10-26。依据当前工作区源码（包含已有未提交修改），不是仅依据早期产品文档。以下问题以静态代码检查为主，尚未用真实照片库验证。

后续进展：已实现进度恢复、保留整批语义和删除期间锁定，并同步传递批次状态通知。详见 [整理流程可靠性优化](session-improvements.md)。以下保留初始评审记录。

## 产品定位

原生 iOS 照片整理工具，使用 SwiftUI、Photos 和 Vision。核心是人工决定保留什么，提供“随机小批次整理”和“相似照片分组”两种入口。当前仅加载图片，不处理视频。

## 已有功能

| 模块 | 当前实现 |
| --- | --- |
| 权限 | 请求照片读写权限；处理未授权、拒绝、受限、完整授权和部分授权；提供设置入口；应用回到前台时检查授权状态变化 |
| 批次整理 | 每批最多 10 张；随机抽样，不足时补齐；剩余少于 50 张改为顺序扫描；批内按拍摄时间升序，同时间按 ID 稳定排序 |
| 筛选 | 上滑加入待删除、左滑保留、右滑撤销；也有对应按钮、进度条和触觉反馈；预加载下一张卡片 |
| 照片信息 | 显示日期、反向地理编码后的地点、可读取的设备型号；地点与设备信息有内存缓存 |
| 批次确认 | 批次结束后手动进入检查页；待删缩略图可逐张恢复；确认后才调用系统删除；有失败提示 |
| 会话管理 | 本次运行内记录处理过的照片；删除后刷新图库并保留会话中的有效资源 ID |
| 相似照片 | 先按相邻照片小于 10 秒的时间间隔聚簇，再用 Vision 特征距离筛选；附加宽高比、尺寸过滤；超大簇分段处理；最多并发生成 6 个特征 |
| 相似组操作 | 边扫描边显示；手动勾选删除；可随机换组、永久忽略整组；忽略记录存 UserDefaults |
| 性能基础 | 图片异步加载、部分请求离屏取消、视觉特征磁盘缓存、扫描退出时取消任务 |

## 第一优先级：可靠性与删除体验

1. **整理进度尚未持久保存。** `BatchManager.setAssets` 会清空已处理 ID，重启后也没有恢复逻辑。建议保存已处理 ID、当前批次、当前位置、待删除集合，按资源 ID 恢复并清理失效项；提供显式“重新整理”。
2. **“暂时跳过”语义不明确。** `skipBatch` 进入下一批但没有清空当前待删集合，后续确认页可能继续带上旧批次照片。建议明确选择：保留本批（清空待删）、稍后处理（独立待办）、继续累积（清楚显示累计数量）。不要让按钮文案与行为含糊。
3. **批次删除时缺少正确位置的交互锁。** 删除遮罩放在滑动页分支，真正执行批次删除时显示的是检查页；检查页没有接收 `isDeleting`，仍能恢复或跳过。建议在根视图统一覆盖删除进度，并禁用会改变会话的操作，保证送交删除的集合与界面一致。
4. **子对象的变化未完整传递给界面。** `ContentView` 观察 `LibraryViewModel`，但读取的是嵌套 `BatchManager` 的发布属性；没有直接观察或转发其变化。需验证检查页逐张恢复、完成页“下一批”等操作能否立即刷新；建议让消费该状态的视图直接观察 BatchManager，或统一状态所有权。
5. **图库外部变化缺少监听。** 未见 `PHPhotoLibraryChangeObserver`；回到前台只在授权枚举变化时刷新。同一授权状态下新增、外部删除或更改部分授权的照片集合，可能无法及时反映。建议订阅图库变化并协调当前会话、相似组与缓存。

## 第二优先级：相似扫描与大图库

- **构建有并发隔离警告。** 实际构建发现 SimilarityService 跨 actor 使用 PhotoAsset 的初始化和计算属性，另有后台任务调用 `deviceText` 的隔离警告；编译器提示部分问题在 Swift 6 语言模式下将变为错误。建议明确纯数据模型和纯解析方法的隔离边界。地点解析还存在 iOS 26 弃用警告，需安排替换。
- **覆盖范围要说清楚。** 当前优先查找连续拍摄的近似照片；跨日期保存的重复图片通常不会比较，不宜描述成“全库重复检测”。可另设精确重复入口，再逐步扩大近似检索。
- **扫描缺少可衡量反馈。** 建议显示已扫描/总数、云端下载状态、失败数量，提供暂停和重试。当前退出可取消扫描任务，但特征生成中的 Photos 请求没有配套取消桥接；应防止离开页面后仍持续下载或等待。
- **相似组的剩余照片可能被隐藏。** 删除成功后整个当前组出队；若只删一张、仍剩多张相似照片，这一轮不会继续处理。建议按删除结果更新组，剩余至少两张时保留在队列。
- **缓存没有版本或资源变更校验。** 特征按 ID 存储；同一照片编辑后可能复用旧特征，删除过的照片也没有清理。建议记录修改日期、Vision 请求版本、特征尺寸和缓存版本，增量刷新并定期淘汰。
- **“忽略此组”不可管理。** 当前持久化忽略整组签名，没有恢复入口。建议设置页提供查看和取消忽略；说明组成员变化后的匹配规则。
- **避免元数据拖慢主体验。** 卡片加载设备信息需要请求图片数据，地点解析也可能依赖系统网络服务。建议延后加载、允许隐藏，优先保障照片浏览；不要宣传完全无网络，云端照片下载和地点解析可能联网。

## 第三优先级：产品完整度

- 增加整理结果：本次已看、已保留、已删除和可解释的空间估算；不要把删除数量当作立即释放空间。
- 增加按月份、相册、截图等入口，以及可调批次数量；避免只有随机整理一种节奏。
- 增加收藏照片保护提示、相似组至少保留一张的提示、放大查看和双图对比。当前没有自动选“最好的一张”，可作为后续辅助能力，仍由用户确认。
- 部分授权需要明确提示“只整理已允许的照片”，并提供管理可访问照片入口；当前有限授权与完整授权基本使用同一界面。
- 图片加载失败时提供重试和明确文案；当前一些路径只显示空白或持续加载，难以区分云端、取消与失败。
- 适配动态字体、VoiceOver、减少动态效果、小屏与横屏；相似照片的点按选择尤其需要可读的选择状态。
- 统一中文文案与权限说明。目前系统照片权限说明是英文；项目最低系统版本配置为 iOS 26.0，可按实际设备需求评估是否降低。
- 补充 README、架构说明、隐私说明和发布材料；当前旧产品文档没有覆盖相似照片能力，且仍保留已落地功能的“待确认”事项。
- 工程中未见测试 target。优先覆盖批次去重、撤销、跳过策略、删除失败后的状态、恢复进度、相似分组边界与取消；真机验证空图库、部分授权、大图库、仅 iCloud 照片、断网、外部删除。

## 建议实施顺序

先修复删除检查页和状态刷新问题，明确“跳过”的含义；再做进度持久化与图库变化监听。之后补齐扫描进度、缓存更新和真机验证，最后扩展筛选入口、统计和辅助选片。这样能先建立用户对“不会误删、不会白整理”的信任。
